IlMatto 性能优化记录（2026-09-10）

本次保持消息内容、界面样式及 33 ms 流式刷新节奏，修改默认 Manager 的保存与显示数据处理路径。

- 会话保存合并约 500 ms 内的请求，UI 线程仅生成独立快照，后台顺序序列化到文件流并原子替换。保存期间的新变化会产生下一份快照；失败保留待保存标记，退出前等待最后一次写入。发送新任务和完成删除也等待必要的保存。
- 后台会话的流式事件不再逐条触发全量保存，相邻普通正文增量合并缓存；工具、思路和状态边界保持原顺序。切回时只重放一次，关闭前处理所有会话的缓存及未显示文字。工具事件前先排出文字队列，防止文字和操作交换位置。
- 计时器只刷新活跃任务，结束时移除订阅，不再每秒扫描全部历史。删除会话也释放对应运行状态。
- 单文本段复用消息正文字符串；加载旧记录时复用相同的正文和单段文本。仍保留原 JSON 字段和多段工具时间线。普通 JSON 文件采用流式读取，带 BOM 的旧编码继续兼容。
- 输入框图片预览改为控件显示时加载、卸载时释放，会话附件模型不再缓存完整位图，避免发送后仍随历史记录长期保留原图解码。保留原分辨率和 WPF 绘制方式，兼容自动布局及各种 DPI；历史图片继续沿用原来的 360 像素宽解码方式。该优化减少预览离开界面后的持续占用，不减少原图显示期间和首次解码的峰值。
- CompanionMemory 的 ensureTranscript 改为文件元数据检查，避免仅为确认存在就读取完整原文。已存在的历史不会被追加或替换。

验证结果：Release 构建 0 警告、0 错误，14 项桌面回归及 8 项 CompanionMemory 测试通过。

桌面回归使用独立临时目录，不连接 Provider、不访问用户凭据、不覆盖真实会话。覆盖保存顺序、合并与失败重试、嵌套快照隔离、旧格式及 BOM 编码、单段和混合段文本、计时通知、后台重放与退出恢复、工具/错误隔离、分配量和图片呈现。图片采用透明渐变、长图、小图和文字截图，在 100%、150%、200%、300% 及 125%、175% 分数像素尺寸下进行离屏对比；另验证实际预览控件的加载、延迟、卸载、重新加载及历史图解码宽度。

同类合成规模下，1,000 条约千字消息单次保存的累计托管分配约 0.50 MiB（原实现审查样本约 24.8 MiB）；64,000 字符以 96 字符一批追加，累计分配约 40.9 MiB（原实现约 81.7 MiB）。分配量不等于常驻或峰值内存，亦不代表整个应用的性能提升比例。图片离屏平均通道差异低于 0.1/255；这不构成所有图片、设备和布局的逐像素一致保证。

本次没有改变历史文件布局、引入按会话磁盘分页、限制历史长度或调整 Provider 热进程上限。后台事件仍在内存中等待切回或正常退出时重放；强制终止进程的恢复能力不因本次优化得到保证。需要进一步减少全部历史模型的常驻内存时，再单独处理会话索引、按需加载和迁移。

滚动抖动后续修复：用真实聊天 XAML 模板在隐藏的 WPF 呈现源中复现了缓存行高偏差。原路径在正文高度上补固定的标题/日期高度，测试中普通行比实际高度多约 12.7 DIP，日期行多约 24.7 DIP；测量缓存又使用气泡宽度，而查询使用整行宽度。消息与占位区域反复替换会因此改变滚动范围。Fenwick 前缀和及偏移查找本身未发现算术错误。

- 改为读取完整 ListBoxItem 的实际高度，测量和查询统一使用滚动视口宽度；卸载的呈现器不再上报延迟测量。
- 文字更新时保留上次真实高度，下一次布局完成后再更新。流式消息与超过 12,000 DIP 的长行也使用真实高度；新增消息不会把现有行重置为估算高度。
- 上方行高度变化时维持当前阅读位置，连续滚动不再丢弃补偿。拖动滚动条时继续按原有队列构建内容：可见区域优先、每批处理两行，不设置速度阈值，也不等待鼠标松开。拖动状态仅用于避免自动偏移补偿与用户操作争抢滚动位置。
- 缓存真实气泡尺寸供占位显示。旧的 UI 高度缓存因几何版本不符被忽略，重新测量后逐步更新；会话文件与附件内容不受影响。

新增回归覆盖 36 条混合文本/图片/日期消息反复显示与卸载、整行高度和滚动总高度一致性、流式/完成/日期变化时的阅读位置、实际滚动条拖动事件、三种窗口宽度，以及随机高度更新后的前缀和与偏移查找。特别验证鼠标保持按下并多次跨区域拖动时，新的 Markdown 内容在松开前就已创建，已测量的滚动总高度保持不变。测试使用生产模板与离屏窗口，没有重启用户正在运行的程序。
